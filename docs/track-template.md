# 新路线标准结构

每条全栈技术路线是 `tracks/` 下一个独立目录。**结构统一是跨路线对比的前提**，新开路线一律按此骨架建立：

```
tracks/<路线名>/
├── README.md      # 路线定位、当前状态
├── roadmap.md     # 学习路线：阶段划分 + 每阶段产出
├── stack.md       # 技术栈选型与约束
├── evaluation.md  # 优缺点、性能与内存特性、适用场景、待验证问题（持续更新）
├── notes/         # 路线专属笔记
└── projects/      # 路线实战项目
```

## 约定

- **命名**：`后端-前端` 缩写，如 `java-ts`、`node-ts`、`go-ts`、`python-ts`
- **建线时**：同步在 `docs/tech-radar.md` 的路线总览表加一行
- **学习中**：性能/内存/优缺点的发现先记入本路线 `evaluation.md`，成熟的结论反哺 `tech-radar.md`
- **evaluation.md 固定章节**：优势 / 局限 / 性能特征 / 内存特征 / 适用场景 / 待实践验证的问题——章节统一，路线之间才能横向对照

# 路线评估：Java + TS（持续更新）

> 目标：对这套栈形成资深判断。以下为初始认知（先验，未经本空间实践验证），学习中持续用实测和踩坑经验修订，结论同步到根目录 `docs/tech-radar.md`。

## 优势

- Spring 生态覆盖企业级全场景：安全、事务、消息、批处理、微服务治理，开箱即用
- 强类型端到端（Java + TypeScript），大型团队协作和长期维护友好
- JVM 工具链成熟：JFR、堆转储分析、async-profiler，线上问题可深挖
- 国内人才市场与资料最充足，招聘与被招聘两端都稳

## 局限

- 开发迭代偏重：启动慢、样板代码多（Spring Boot 3 已减负，但仍重于脚本语言栈）
- 内存基线高，小规格容器和 Serverless 场景不友好
- 冷启动慢；GraalVM native-image 可解，但对反射/动态代理有约束，付出构建复杂度

## 性能特征

- JIT 预热后吞吐属第一梯队，适合长驻高负载服务
- GC（G1/ZGC）停顿可控，但需要理解代际、堆大小与停顿目标的权衡
- Java 21 虚拟线程大幅改善高并发 IO 场景，传统线程池模型正在被替代

## 内存特征

- 进程内存 = 堆 + Metaspace + 线程栈 + 直接内存，容器内必须显式设限（`-Xmx` 或 `MaxRAMPercentage`），否则容易被 OOMKill
- 对象头与指针开销大，同等服务的内存占用普遍高于 Go / Node
- 内存问题高发点：缓存无界增长、ThreadLocal 泄漏、大对象晋升引发 Full GC

## 适用场景

- 适合：中大型企业后台、复杂业务域、长驻高吞吐服务、对事务与一致性要求高的系统
- 不适合：内存敏感的边缘/Serverless 部署、追求极致迭代速度的小团队原型
